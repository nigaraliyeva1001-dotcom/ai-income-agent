# Модерация карточек mp-content.umico.az (единый навык)

Объединяет четыре прежних навыка: общую модерацию карточек, помощника с чек-листом по одной карточке, присвоение Variation/Search Code по фото и проверку ВГХ по регламенту (правила в файле vgh-rules.md рядом с этим файлом). Цель: один проход на карточку, ничего не повторять и не опрашивать по много раз, всё сразу правильно.

## 0. Старт: всегда дать выбор
Перед работой один раз задать Нигяр вопрос через AskUserQuestion с вариантами режима. Если она уже указала режим в сообщении, не спрашивать.
- Полная правка: проверка, исправление и «Подтвердить» по каждой карточке.
- Только проверка: ничего не сохранять, выдать отчёт.
- Только Variation/Search Code: найти группы вариантов и присвоить коды.
- Пробная партия: первые 20–30 карточек для оценки качества.
Такой же выбор вариантов предлагать каждый раз, когда на пути встречается развилка (дубль или варианты, спорный случай, неизвестная категория), вместо вопроса в свободной форме.

Один раз прочитать vgh-rules.md (этот навык) и из памяти проекта своды naming-rules.md, moderation-decisions.md, preferences.md (шаблоны названий, переводы, коды) и держать как постоянный контекст. Указание Нигяр в чате главнее свода.

## 1. Вход
Список ID, ссылка на /moderation с фильтрами или фильтр. Очередь Нигяр: appointed_moderator_id_eq=5d203875-dac9-47b5-91e7-8542455f9479, status draft, moderation_status new. Работать только с карточками, назначенными на неё, или с ID из её списка.

## 2. Запреты
- Никогда «Автозаполнение», «Сменить статус на Готов к публикации», «Вернуть карточку для редактирования». Только «Подтвердить» (успех: всплывающее «Товар успешно отредактирован» или переход на /products/ID).
- Принять, вернуть или опубликовать решает Нигяр. Исключение: вернуть партнёру можно только когда нет фото либо подтверждён дубль (п. 6.2 и 6.8).
- Не менять данные продавца (длина, размеры, вес и т.п.), только сообщать, если выглядят неверными. Ничего не удалять, кроме прямо указанного.
- Комментарии партнёру не сочинять: только готовые шаблоны из списка в админке и два текста Нигяр. ВГХ: «Bu bağlamanın ölçüləri düzgün qeyd edilmiyib». Дубль: «{ID оригинала} ile siz bu məhsulu artıq əlavə etmisiniz» (ставится в иконке-комментарии у поля AZ-названия, затем сохранить). Нет фото: шаблон «Şəkil əlavə edin».
- Не переписывать описания. AZ — оригинал продавца, RU — перевод AZ. Если у продавца только RU, AZ = перевод RU. Пустое описание не выдумывать, а вносить в отчёт.
- Не сохранять оранжевые (новые) значения атрибутов: выбрать существующее. Исключения: цвет и размер (новое значение с заглавной буквы) и вес, если такого веса нет (сначала прокрутить выпадающий список, поиск показывает только 10 результатов). Значения, которые Нигяр велела оставить оранжевыми, не сохранять, карточку оставить ей.
- «Леопардовый» как значение не добавлять. bordo = «Tünd qırmızı» (AZ) / «Бордовый» (RU). Вес в файлах с точкой (0.39).
- Материал в атрибуте = материалу в названии.
- Не трогать токены и учётные данные, не вызывать API в обход интерфейса. Если Нигяр в этой сессии явно разрешила пакетную работу через API, действовать в рамках её разрешения и не выводить токен.
- Не объединять товары разных партнёров и не присваивать VC/SC одиночным товарам.
- Если Chrome блокирует страницу, 2–3 попытки подряд падают или потеряна сессия, остановиться и спросить.

## 3. Название (RU, затем AZ)
Шаблон: Тип + Бренд/Код + Пол (одежда/обувь/сумки) + Цвет + Материал + Размер/Объём.
- Тип товара одно значение. Бренд/линейка как написано в обоих языках; поле «Производитель (Brand)» проверять всегда.
- Цвет и материал строчными, несколько через «/». Размер всегда последним: «ölçü {X}» / «размер {X}», неясный: «One size». Без «ё», «парфюм» вместо «духи».
- No Brand без кода: вставить код сразу после типа. Если код уже в названии, свой не добавлять. Бренд+модель через пробел, без запятой.
- Электроника: Тип + Бренд + Модель + Мощность/Объём + Цвет; гарантия ≥ 6 мес.
- Часы: тип с полом + бренд/код + модель + цвет; слова о механизме, циферблате, ремешке удалять.
- Ювелирка: Тип + код + «qadınlar üçün» / «для женщин», затем запятая и материал+проба одним блоком: «qızıl 585 əyar» / «золото 585 пробы» (никогда «проба»); «Turk» удалять.
- Переводы цветов: mavi=голубой, göy=синий, parça=текстиль, qızılı=золотистый, gümüşü=серебристый, lacivərt=темно-синий.
- Комплекты ювелирные (кат. 2325). AZ: «Zinət dəsti {артикул} qadınlar üçün, qızıl 585 əyar, {состав через запятую и «və»}, {вес} q». RU: «Ювелирный комплект {артикул} для женщин, золото 585 пробы, {состав через запятую и «и»}, {вес} г». Если у кольца два размера, указать оба. Цепочка с кулоном на фото: можно «Цепочка с кулоном…» вместо «Колье».
- Полные правила по категориям в naming-rules.md. Для новой категории без шаблона один раз спросить пример названия и предложить обновить навык.

## 4. Чек-лист на ОДНОЙ карточке (один заход)
Полная модерация это всё сразу: название, описание, атрибуты, фото, ВГХ, варианты и дубли. Если нет возможности сделать всё за один проход, лучше не трогать карточку, чем подтвердить недоделанную.
1. Чтение одним JS: категория, партнёр, MPN, бренд, названия RU/AZ, атрибуты (оранжевые отдельно), описания (из редактора на странице карточки, не из таблицы), ВГХ, фото, дата создания, коды вариации.
2. Фото: ~800×1000 (3:4), png/jpg/webp до 15 МБ, чистое, соответствует категории и цвету, без рекламы и чужих логотипов, не размытое, не коллаж.
   - Нет фото: комментарий «Şəkil əlavə edin» и вернуть партнёру.
   - Реклама, размытое, не соответствует: комментарий-шаблон, в отчёт «вернуть: фото», решает Нигяр.
   - Фото с 2–3 цветами или размерами, либо в описании «разные/несколько цветов (размеров)» и фото это подтверждает: НЕ подтверждать, оставить как есть, внести в список проблемных. Каждый размер и цвет должен быть отдельной карточкой.
3. ВГХ: полная проверка по разделу 4а и vgh-rules.md (не только сверка с классом доставки).
4. Название по п. 3, RU и AZ.
5. Атрибуты: заменить оранжевые существующими по фото и данным продавца, заполнить обязательные (мин. 4 мастер-атрибута), бренд существующий или No Brand (красное заменить), несоответствие описанию в отчёт. Если нужного цвета нет (например «Разноцветный» в серьгах), оставить пустым или определить по фото. Пример: «Тип/Tip» = «Qolbaq» (оранжевое) заменить на «Мягкий»/«Yumşaq».
6. Описания: перевести недостающий язык, не меняя смысл, и проверить, что RU и AZ совпадают.
7. Variation/Search Code по п. 5, только если у ОДНОГО партнёра есть варианты одного товара.
8. Дубли только у того же партнёра. Дубль лишь если совпало ВСЁ: название, MPN/артикул, фото (то же изображение) и характеристики (цвет, размер, объём, габариты). Одно расхождение значит НЕ дубль.
   - Подтверждённый дубль: оставить оригинал, на новой карточке комментарий дубля и вернуть партнёру. В отчёте ID оригинала и месяц/год.
   - Частичное совпадение: не возвращать, в отчёт «возможный дубль {ID}, {месяц год}, совпало / разошлось».
9. «Подтвердить».

## 4а. ВГХ (вес и габариты упаковки)
Полные правила, таблицы категорий и примеры в vgh-rules.md. Читать один раз в начале работы и держать в контексте.
1. Прочитать поля на странице карточки: «Длина, мм (в упаковке)», «Ширина, мм (в упаковке)», «Высота, мм (в упаковке)», «Вес, кг (брутто)». Стороны всегда в мм, вес в кг. Объём м³ = Д×Ш×В / 1 000 000 000.
2. Определить тип доставки по самому большому показателю: Пакет (<1 кг и все стороны <350 мм), Стандарт (1–30 кг, стороны ≤1200 мм, объём ≤0,12 м³), КГТ (>30 кг, или сторона >1200 мм, или объём >0,12 м³), КГТ+ (>60 кг или объём >0,46 м³).
3. Проверка за 5 шагов, на первой ошибке стоп:
   1) цифры заполнены (нет нулей и пустых полей);
   2) единицы верные: см вместо мм (кроссовки 33×22×12 → 330×220×120), граммы вместо кг (350 → 0,35);
   3) правило категории из vgh-rules.md, а если категории там нет, тип из categories.xlsx, лист «Категории и типы» (правило категории главнее всего; при «Пакет + Стандарт» без цифр брать меньший тип);
   4) цифры не спорят с названием: мл→г (1 мл = 1 г; у масел 1 л ≈ 0,9 кг), кг, шт, рулоны, диагональ ТВ; литры посуды и рюкзаков — это вместимость, не вес; «140 кг» у самоката и «9-36 кг» у автокресла — нагрузка, не вес;
   5) всё сошлось — принять как есть.
4. Размер вещи ≠ размер упаковки: текстиль, разборная мебель, надувные и складные вещи (палатки, бассейны, коляски) — стандартные цифры своего типа, не размер из названия. Запас на коробку не добавлять, третью сторону не придумывать, у круглых предметов третья сторона = диаметру.
5. Решение:
   - ВГХ неверный, но тип доставки для категории получается правильный: не трогать и не комментировать.
   - Ошибка очевидна, и тип не сходится с категорией: по умолчанию цифры НЕ менять (это данные продавца), поставить комментарий «Bu bağlamanın ölçüləri düzgün qeyd edilmiyib», в отчёт записать текущие цифры и правильные по правилу (например «33×22×12 см → 330×220×120 мм, Стандарт»). Сами цифры менять только если Нигяр явно попросила это в текущем запросе.
   - В правиле «решает КМ», товар не похож на категорию или цифры правдоподобны, но тип не совпадает: ничего не менять, в отчёт «КМ: что проверить».
6. Запись (только по явной просьбе Нигяр): native setter `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` + события input/change, затем «Подтвердить» и ждать ухода со страницы /products/edit/{id} поллингом. Цифры не ставить ровно на границе типа (1 кг, 30 кг, 350 мм, 1200 мм).
7. В отчёте отдельная колонка ВГХ: «ок» / «комментарий: было → должно, тип» / «КМ: причина».

## 5. Variation/Search Code (размерные и цветовые варианты)
Нужны только группам вариантов одного товара у одного партнёра; одиночным товарам оставлять плейсхолдеры VC_<id>/SVC_<id>.
1. Сбор (только чтение): id, nameRu, nameAz по всем ID из очереди. Если собирать из таблицы /moderation, пагинация программным «next» ненадёжна: после клика ждать смены `.el-pagination .is-active` (до 5 с), дедуплицировать по id и сверить количество с названным пользователем; прогресс хранить в localStorage.
2. Группировка: из nameRu отрезать размер регуляркой `/,?\s*\d+\s*$/`, сгруппировать подряд идущие по возрастанию ID товары с одинаковым базовым именем, у которых разница ID с предыдущим ≤5 (разрыв больше 5 значит другая партия). Группы из одного элемента пропустить. Выборочно сверить фото 1–2 пар.
3. Коды: Variation Code = минимальный ID группы. Search Code = `{VC}_{цвет}`, цвет на русском, строчными, последнее слово nameRu без размера (например `3209941_черный`); если у продавца в nameRu азербайджанский цвет, подставить русский, не меняя поле названия. У всех товаров группы одинаковые VC и SC. Для карточки из шаблона «Search = Variation_цвет на языке названия» использовать язык названия, если Нигяр так указала.
4. Запись только на `/products/moderation/{id}` (на `/products/edit/{id}` поля disabled). Через native setter: `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set`, события input и change на полях «Код вариации» и «Search код вариации», пауза ≥800 мс, клик «Подтвердить», пауза ≥2500 мс. Успех: pathname стал `/products/edit/{id}`. Паузы короче не сохраняются при ложном успехе.
5. Проверка: прочитать реальные значения полей у 4–5 товаров, равномерно по очереди, и у всех с ошибкой. Если остались VC_<id>/SVC_<id>, повторить запись.

## 6. Порядок работы
1. Сбор (только чтение) по всем карточкам: атрибуты, описания, вес, артикул, фото, группы дублей и вариантов. Проверить, что ни одно описание не пустое (пустые в отчёт).
2. Подготовка офлайн: названия RU/AZ, переводы, значения атрибутов, группы VC/SC.
3. Запись по одной карточке в активной вкладке после перезагрузки страницы (в фоновых вкладках выпадающие списки ненадёжны). Партии 30–40 карточек, один длинный скрипт на партию, без пересказа шагов; прогресс копить в localStorage.
4. Одна финальная проверка чтением после перезагрузки; повторять только для карточек с ошибкой.

## 7. Технические заметки (Nuxt 3 + Element Plus)
- Просмотр /products/ID, редактирование /products/edit/ID, модерация /products/moderation/ID, список /moderation.
- Роутер: `document.querySelector('#__nuxt').__vue_app__.config.globalProperties.$router` (может быть недоступен; тогда navigate). Результат javascript_tool с «=» между подписью и значением или с query-строкой блокируется как данные cookie/URL, поэтому разделять «->».
- Селекты `.el-select__wrapper`, опции `.el-select-dropdown__item`, теги `.el-tag`, оранжевый `.el-tag--warning`, закрытие `.el-tag__close`, ошибки `.el-form-item.is-error`.
- Названия: textarea[0]=RU, [1]=AZ, `el.select()` + `document.execCommand('insertText')` (прямая установка value не сохраняется).
- Описания: `.tiptap.ProseMirror` [0]=RU, [1]=RU outlet, [2]=AZ, [3]=AZ outlet; focus, selectAll, insertText.
- «Добавить Атрибут +» требует реальных кликов (скриншот → координаты). Добавление уже существующего значения даёт 422.
- После navigate ждать ≥10 с.

## 8. Отчёт (единственный текст пользователю)
Таблица: ID | что исправлено | ВГХ | результат (на сайт / возвращена: нет фото / возвращена: дубль {ID оригинала}, {месяц/год} / вернуть + причина / возможный дубль / не уверен). В конце: ID без проблем, которые можно публиковать, список проблемных ID с причиной (мультицвет, мультиразмер, пустое описание, ВГХ с цифрами «было → должно», КМ) и вопросы к Нигяр. Для VC/SC добавить число групп, число товаров, распределение по цветам и ручные исключения. Коротко.
